# 기숙사 출석체크

참고 이미지의 흰 배경, 원형 학교 마크, 밑줄 입력창, 초록색 로그인 버튼으로 만든 Next.js 프로젝트입니다. 마크는 참고 이미지를 바탕으로 SVG로 재구성했으며, 공식 원본이 생기면 `public/school-mark.svg`를 교체하면 됩니다.

## 실행

Node.js 22.13 이상이 필요합니다.

```sh
npm install
npm run dev
```

터미널에 출력된 주소에서 접속합니다. 기본은 <http://localhost:3000>이며, 개발 모드는 포트가 사용 중이면 3001~3010 중 비어 있는 포트를 선택합니다. 개발 전용 테스트 계정은 **student / dorm1234!** 입니다. 로그인 → 오늘의 출석 → 출석체크 → 최근 기록 확인 흐름으로 동작합니다. 이 계정과 로그인 안내는 운영 모드에서 비활성화됩니다.

## 기숙사 IP 붙여 넣기

현재 허용 IP는 **`172.28.10.29` 한 개**입니다. 이는 특정 기기의 내부 IP이며, 같은 Wi-Fi의 다른 기기까지 허용하는 설정은 아닙니다. 현재 Mac에서는 `http://172.28.10.29:3001`처럼 접속하세요. 실제 포트는 실행 로그에서 확인합니다. 개발 모드에서 `localhost`로 로그인/출석 페이지를 열면, 허용된 IP가 이 Mac의 실제 네트워크 주소인 경우 해당 주소로 자동 이동합니다. IP 검사는 그대로 유지되므로 로컬 API 요청의 출석 우회는 허용하지 않습니다.

`config/attendance.ts`의 배열을 수정하면 됩니다.

```ts
allowedNetworks: ["여기에_실제_기숙사_IP"],
```

여러 IP, IPv4/IPv6, CIDR 대역을 지원합니다. 예: `["203.0.113.10", "192.168.10.0/24"]` (문서용 예시이므로 실제 주소로 교체). 인터넷에 배포하는 경우 **기숙사 공유기의 공인 IP**를 넣으세요. 같은 Wi-Fi에 연결된 학생들은 일반적으로 같은 공인 IP로 접속합니다. 공인 IP가 변경되면 허용 목록도 갱신해야 합니다. 내부망 서버라면 서버에서 보이는 내부 IP/CIDR을 사용합니다. IP 확인은 네트워크 소속을 판단하며 물리적 위치나 VPN 사용 여부를 증명하지는 않습니다.

환경변수를 선호하면 `.env.example`을 `.env.local`로 복사하고 아래 주석을 해제합니다. 환경변수는 배열보다 우선합니다. 변경 후 서버를 다시 시작하세요.

```dotenv
ATTENDANCE_ALLOWED_IPS=203.0.113.10,203.0.113.20
```

**허용 IP 미설정, 잘못된 설정, IP 확인 실패, 외부 네트워크 접속은 모두 출석을 차단합니다.** 로컬에서 성공 흐름을 시험하려면 일시적으로 `allowedNetworks: ["127.0.0.1", "::1"]`을 사용하고 테스트가 끝나면 실제 IP로 바꾸세요. 개발 모드에도 IP 검사 우회는 없습니다.

## 실제 학생 계정 만들기

```sh
npm run user:add -- 20260001 "홍길동"
```

프롬프트에 8자 이상의 비밀번호를 입력합니다. 비밀번호는 화면에 표시하지 않으며 scrypt 해시로 저장됩니다. 기존 아이디를 덮어쓰지 않습니다. 현재는 자체 학생 계정이며 학교 계정 시스템과 연결되어 있지 않습니다.

## 출석과 로그인 처리

- 서버에서 접속 IP를 확인하고, 출석 요청마다 허용 목록을 다시 검사합니다.
- 브라우저가 보낸 IP나 `X-Forwarded-For`를 그대로 신뢰하지 않습니다. `server.mjs`가 소켓의 실제 주소를 확인한 뒤 내부 서명으로 Next.js에 전달합니다.
- `Asia/Seoul` 기준 하루 한 번 출석하며, DB의 고유 제약으로 동시·중복 요청도 한 건만 저장합니다.
- 학생·출석·서버 세션은 SQLite `data/dorm.sqlite`에 저장되어 재시작 후 유지됩니다.
- 로그인 쿠키는 HttpOnly이며 12시간 유효합니다. 로그아웃 시 서버 세션도 삭제합니다. 로그인 실패 5회 시 해당 아이디는 15분간 제한됩니다.
- 로그인·로그아웃·출석 요청은 같은 출처인지 확인합니다.

## 운영 환경

```sh
npm run build
npm start
```

**반드시 위 스크립트를 사용하세요.** `next dev` / `next start`를 직접 실행하면 접속 IP를 검증하는 커스텀 서버가 생략되어 출석을 차단합니다. 운영 쿠키는 HTTPS에서만 전송되므로 운영 서버는 HTTPS 프록시 뒤에서 실행합니다. 기본 포트는 3000이며 `PORT`로 변경할 수 있습니다.

프록시 없이 실행하면 추가 설정은 없습니다. Nginx 등 프록시 뒤에서는 배포 환경에 **실제 프록시 주소만** `TRUSTED_PROXY_CIDRS`로 지정하고 `APP_ORIGIN`을 실제 서비스 주소로 설정합니다. 프록시가 `X-Forwarded-For`를 실제 주소로 덮어쓰거나 뒤에 추가하도록 설정해야 합니다. `0.0.0.0/0`처럼 모든 접속자를 프록시로 신뢰하면 안 됩니다. 예시:

```dotenv
TRUSTED_PROXY_CIDRS=127.0.0.1/32,::1/128
APP_ORIGIN=https://dorm.example.com
```

Node.js와 **영구 저장 디스크를 갖춘 단일 서버**용 구현입니다. 서버리스·다중 서버 배포 시 계정·세션·출석을 공유하는 DB로 이전해야 합니다. `DORM_DB_PATH`로 DB 위치를 바꿀 수 있으며 DB와 WAL 파일은 함께 백업해야 합니다. DB를 삭제하면 계정과 출석 기록도 없어집니다. 실제 운영 전 학생 계정을 등록하세요.
